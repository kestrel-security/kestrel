# README screenshots

The images in this directory are captured from a real, locally running Kestrel
against the `make demo-up` estate — synthetic tenants and fictional people, no
tenant data. They are not mockups. Re-capture them when the UI changes; a
change that invalidates one of these is not finished until the image is
updated.

## Capturing

`make screenshots` re-captures every image from a running demo, using
[`scripts/capture-screenshots.mjs`](../../scripts/capture-screenshots.mjs):

```bash
make demo-up                                   # four fixture tenants + the drift timeline
pnpm exec playwright-core install chromium     # once
make screenshots                               # every image
make screenshots ONLY=finding-detail           # one image, by file stem
```

The script signs in as `admin@kestrel.local` through the API, looks up the
subjects below (demo ids are regenerated by every `demo up`), and renders each
route in the dark theme at a device scale factor that lands the image exactly
1800px wide. It then crops it to its content: the viewports below are capture
heights, and a page whose content ends early is trimmed so the README does not
carry a band of empty background. Toasts and the unread-notification badge are
hidden.

Two traps the trim handles. A dashboard board is a react-grid-layout: its
container reserves empty rows below the widgets, and a widget whose list
overflows its cell leaves text *below* the card — so it measures the bottom of
the `.react-grid-item` elements, not of the deepest descendant. Everywhere
else it measures the lowest leaf element that actually renders text or media;
a plain "deepest descendant" measurement hits full-height layout containers
and trims nothing.

`<person>` is a person correlated across all four applications, preferring
one who is privileged and has MFA off (the README caption tells that story);
`kestrel demo verify` reports how wide the widest correlation is.

The web UI is built into its image rather than bind-mounted:
`docker compose up -d --build web` after a change under `apps/web/`, or the
screenshots will show the previous build.
